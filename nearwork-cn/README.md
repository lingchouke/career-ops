# 近职

Windows 本地中文求职工具。双击 **start.cmd**，点击「载入示例」，可以试用三个虚构岗位。示例地址与耗时只用于演示。关闭窗口会清除本次资料，需要保留的岗位请先导出对照。

## 用自己的资料

1. 在「简历与通勤」导入 PDF（文字版）、Word（DOCX）、TXT 或 Career-Ops 的 cv.md，也可粘贴正文。填写城市、出发地、日期、时刻和通勤上限。扫描件须先 OCR。
2. 粘贴一个 JD，按《岗位模板.csv》批量导入，或读取 Greenhouse 企业招聘板。默认示例 miqdigital 只查询该企业在所选城市的公开职位；每次刷新会用当前返回的岗位替换该来源的旧列表。手工导入的岗位请自行核实在招状态。英文城市别名覆盖沪、京、深、广、杭、蓉、苏、港，其余城市可输入招聘方使用的地名。
3. 选择岗位，确认实际门店地址。填写高德 Web 服务 Key 后可查询单个岗位或每批最多 20 个同城地址的公交及地铁路线。也可以手工录入自己核实的单程耗时。更换出发点、日期、时刻或工作地址会重新判断通勤。只有已知耗时才会归入「范围内」。
4. 阅读岗位要求与简历原文对照，按追问补充本人确实做过的事。第一版采用文本与中文经验词表，主要覆盖门店、运营、客服；“有相关原文”只表示找到了线索。未提及的能力标为待确认。
5. 点击「加入 Career-Ops 评估」。模块使用上游的数据目录解析和技能比对函数，归档岗位到个人数据目录的 `jds/nearwork/`，再通过原生 `agent-inbox.mjs` 加入待评估队列。在本仓库的 AI 会话执行 `/career-ops agent-inbox`，按 oferta 流程继续。也可只导出 Markdown 对照。示例岗位不能进入真实队列。
6. 已有主简历时，可以用「读取 Career-Ops 主简历」载入它。窗口正文和主简历不一致时，加入队列会提示先同步。有意更新主简历时，先核实并在 Career-Ops 中更新 cv.md，再重新读取。首次创建 cv.md 需要确认。

## 运行环境与联网

启动器优先使用本机 Codex 附带的 Python。其他 Windows 电脑可安装含 Tk 的 Python 3.10+ 和 Python Launcher，在本目录运行 `py -3 -m pip install -r requirements.txt`，再启动。PDF 和 DOCX 导入使用这两个依赖。

集成功能需要满足仓库 package.json 要求的 Node.js，并先在仓库根目录运行 `npm install`。主简历、已归档岗位和收件箱会保留在上游数据目录中。

简历分析在本机完成。读取企业招聘页时仅发送招聘板请求。查路线时向高德发送密钥、城市、地址、坐标、日期及出发时刻。密钥可在窗口输入或通过 AMAP_WEB_KEY 环境变量提供。未配置密钥时仍可用手工核实的耗时筛选。招聘页只有城市或区域的岗位，不能据此推断具体上班地址。

接口说明：[Greenhouse Job Board API](https://developers.greenhouse.io/job-board.html) · [高德公交路径规划](https://lbs.amap.com/api/webservice/guide/api/direction)。
