# 近职求职助手
在项目文件夹里双击「启动近职」。如果你在代码目录里打开本说明，请双击同目录的 start.cmd。

1. 首页显示本机已有的岗位数量和最近更新时间。第一次使用没有数据时，点「更新岗位数据」，等更新完成。上传能复制文字的 PDF、Word（DOCX）或文本简历，输入工作城市，选择公司所属行业，填写岗位关键词，然后点「查找岗位」。关键词会在岗位名称和描述中查找，可以留空。
2. 查找只使用本机已保存的岗位，断网也能用。已分析的岗位按程序计算的分数优先排列，显示岗位、公司、地点和匹配度。点一行进入该岗位。没有结果时，可放宽条件；要获取新发布的岗位，请回首页点「更新岗位数据」。
3. 未分析的岗位显示「未分析」，旧报告显示「需要重新分析」。点开岗位后，首次使用可点「AI 服务设置」，填写兼容 Chat Completions 的服务地址、模型名称及所需密钥。详细分析先给结论、最该先补的事项，再列必须和加分欠缺项、部分满足项。点「展开」可看已满足项和简历证据。方向明显不同时只显示整体结论和更合适的岗位方向。

岗位搜索和初筛在本机完成。首次详细分析会将简历文字和岗位描述发送给选定的 AI 服务；程序替换邮箱和常见大陆手机号，但其余经历仍会发送。运行时读取仓库根目录的 `prompts/analysis.md`。成功结果保存到本机的 `analysis-cache.sqlite3`，材料与提示词相同就直接读取。删除该文件可清除保存的分析。分析页只展示能在原始简历逐字找到的引文。

如果你在别处看到岗位，上传简历后点「粘贴岗位描述」，贴入职责和任职要求，点「对照我的简历」，即可使用相同的详细分析。

服务设置仅在本次运行有效。如需预设，可在启动前设置环境变量 `OPENAI_BASE_URL`、`OPENAI_MODEL` 和 `OPENAI_API_KEY`。模型需支持 JSON 对象输出、temperature 为 0 和至少 8192 个输出 token。首次输出截断后会以 16384 个 token 重试一次。

维护岗位来源：编辑同目录的 `companies.json`。每家公司的 `type` 填 `greenhouse` 或 `lever`，`slug` 填招聘页的公司标识，`name` 填显示名称，`industry` 填求职者看到的公司类型。Lever 欧洲站另加 `"region": "eu"`。

点击更新或在此目录运行 `python sync_jobs.py`，即可将各家公司所有地点的公开岗位写入 `jobs.sqlite3`。只在整家公司的列表下载成功后替换它的旧岗位；读取失败会保留上次的数据。从清单中移除的公司会在更新后退出岗位库。命令行也可用 `--config` 和 `--db` 指定其他文件。接口说明：[Greenhouse](https://docs.greenhouse.io/job-board.html)、[Lever](https://github.com/lever/postings-api)。

公司行业与公司性质分开筛选。公司性质依据 companies.json 中的国内口径 domestic 和海外注册形式 foreign_form 标注，表示已配置的招聘企业，不保证等于当地签约子公司。可填国企、民企、外企或当地法定形式，未知留空。

点「更多条件」设置可接受的最低门槛、人民币月薪范围或语言（例如英语或流利）。月薪按区间重叠匹配。默认包含未写明；取消后排除字段缺失的岗位。「只看未写明的」可按字段组合。点击列表列头可以排序。汇率采用 fx.json 中注明日期的欧洲央行参考值，年薪除以 12，原币种保留；无可用汇率时仅显示原币。

点「补充提取」或运行 python sync_jobs.py backfill，即可为旧库补充数据。同步时按来源和描述指纹增量处理；设置模型后，每批最多 4 个岗位，只提交缺失字段和岗位描述，已完成批次保存在本机。失败最多尝试 3 次，再次点击继续。运行 python sync_jobs.py audit 随机抽查 20 条，查看原文和结果。

评分配置位于 scoring.json。每条要求仅在证据逐字可核实时获得对应权重；硬性门槛和方向不符会限制最高分。详细分析和列表都用同一配置重新计算已保存报告的分数。
